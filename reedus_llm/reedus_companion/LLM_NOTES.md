# why the llm is the way it is

- **base model, no fine-tune.** reedus is Qwen2.5-3B-Instruct (Q4_K_M) base. I tried the fine-tune route twice (mistral-7b LoRA in `reedus_llm/*.py`, then QLoRA + DPO on Qwen3-4B in `train/`) and it destroyed the model: the fine-tune learned a weird flat register and lost the base model's energy, public dialogue data leaked other identities in, and safety/refusal behavior degraded. the whole reedus character now lives in the system prompt (`serve/persona.py`).
- **3B over 4B.** ~6.4 tok/s vs ~4 on the xeon and the persona held up in the comparison, so the smaller one is better. 7.8 tok/s is the machine's ceiling due to hardware limits.
- **cpu only.** the run box is a 14-core Xeon E5-2680 v4 with 16 GB and no usable gpu, so everything is llama.cpp (native `llama-server`, AVX2/OpenBLAS build), int8 whisper, cpu kokoro, and the thread budget leaves 2 cores free so the mic doesn't fail.
- **prefill is the latency.** a turn is several model calls with different system prompts. so: multi-slot prompt cache, volatile blocks (passages, recall, bulletin) go after history not in the system message, history advances in chunks, and every prompt is warmed at boot.
- **router split.** the 10-30 token JSON classifier calls (search router, look router, extract) run on a 1.7B. the ones it measurably messes up (subjects, correction, topic-brief, look-router) stay on the main model.
- **cheap-turn gates.** over half of a chitchat turn was guard calls that couldn't change anything. regex gates skip the router / draft check only when there's zero signal.
- **knowledge corpus.** a 3B doesn't know things, so there's a local sharded wiki/fandom passage store (bge-small embeddings, int8 so it fits page cache, mmapped, LRU). retrieval is gated because a simple greeting used to trigger a corpus search. a grounding filter decides relevance.
- **search.** self-hosted SearXNG because one engine gives one snippet per page and it's usually very random; DDG is the fallback. weather bypasses all of it and uses open-meteo directly.
- **grounding.** drafts with risky claims (numbers, years, scores, outcomes) get verified by a search + regenerate, a digit guard makes sure the reply doesn't contradict the fact, and invented dialogue / unattested names get scrubbed. speak-first acks so a 30s search turn doesn't feel frozen.
- **corrections become data.** when the user corrects him it's logged with corpus evidence and put into DPO pairs, and pinned facts go in the bulletin so he never contradicts them.
- **voice.** faster-whisper `base`, kokoro-82M paced per sentence, a locally trained openWakeWord "hey reedus" model (two syllables was too thin, and whisper hears "readers"), and wake-word barge-in while he's thinking or talking.
- **cloud mode.** because the persona is just a prompt, swapping the brain for gemini 3.7 flash and the voice for inworld TTS-2 is free. ~$20/month with a budget breaker that drops back to local. the corpus is off in cloud mode, it only added latency there.
